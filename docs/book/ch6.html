Chapter 6

Event bus & reporting

How does a test result become a report without the test knowing what a report is? Through a publish/subscribe event bus. Keywords announce results; a recorder listens. Neither knows the other exists.

The bus — tiny but powerful

All of event_bus.py that matters:

class EventBus:
    def __init__(self) -> None:
        self._subs: dict[str, list[Subscriber]] = defaultdict(list)

    def subscribe(self, topic: str, handler: Subscriber) -> None:
        self._subs[topic].append(handler)

    def publish(self, topic: str, **payload) -> None:
        event = Event(topic=topic, payload=payload)
        for handler in self._subs.get(topic, []):
            handler(event)
Analogy A radio station. The keyword broadcasts on a frequency ("test.result"); anyone tuned in receives it. Add a second listener (a live dashboard, a spreadsheet writer) and the broadcaster changes nothing.
Why defaultdict(list)? The first time anyone subscribes to a topic, the list is created automatically — no "if the key doesn't exist yet" bookkeeping. Small idiom, cleaner code.

The recorder listens and grades

From report_recorder.py. In its constructor it subscribes; from then on it quietly accumulates every result:

class ReportRecorder:
    def __init__(self, bus: EventBus) -> None:
        self.cases: list[CaseResult] = []
        bus.subscribe(RESULT_TOPIC, self._on_result)

    def _on_result(self, event: Event) -> None:
        p = event.payload
        case = self._get_case(p["suite"], p["case"])
        case.steps.append(StepResult(check=p["check"], expected=p.get("expected", ""),
                                     measured=p.get("measured", ""), outcome=p.get("outcome", "PASS")))

Grading rolls up the steps — any FAIL fails the case; a CHECK downgrades but doesn't fail:

@property
def outcome(self) -> str:
    outcomes = {s.outcome for s in self.steps}
    if "FAIL" in outcomes:
        return "FAIL"
    if "CHECK" in outcomes:
        return "CHECK"
    return "PASS"
Why three outcomes, not two? CHECK means "measured, worth a human's eye, but not a failure" — for example an expected pre-calibration error. Collapsing it into PASS or FAIL would hide real information.
What breaks if keywords kept their own results list You'd be back to tangled code: every new output format would mean editing every test. The bus is what keeps the tests ignorant of reporting — and that ignorance is a feature.

Quiz 1 — How would you add a JSON report without touching any test?

Write a second subscriber to RESULT_TOPIC that writes JSON. The bus delivers to it alongside the Markdown recorder; keywords never change.

Quiz 2 — A case has steps PASS, PASS, CHECK. What's the case outcome?

CHECK — no FAIL present, but a CHECK downgrades the overall result.
