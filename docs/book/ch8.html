Chapter 8

Robot suites & the whole loop

The top layer is where a non-programmer can read what's being tested. Robot Framework files describe intent; a thin library connects that intent to the engine.

Layer 1 reads like English

hiltf/layer1_suites/overcurrent.robot:

*** Settings ***
Library           HiltfLibrary.py
Suite Setup       Open Bench
Suite Teardown    Run Keywords    Write Report    reports/overcurrent.md    AND    Close Bench

*** Test Cases ***
Overcurrent Detection All Scenarios
    Run All Cases      overcurrent    config/overcurrent_plan.csv
    All Cases Passed
No Python, no addresses here. Everything concrete lives below. This file could be reviewed by a test engineer who never writes code — which is exactly who often owns the test plan.

The adapter bridges the two worlds

HiltfLibrary.py exposes engine calls as Robot keywords:

@library(scope="SUITE")
class HiltfLibrary:
    def __init__(self) -> None:
        self.bus = EventBus()
        self.recorder = ReportRecorder(self.bus)

    @keyword
    def run_all_cases(self, kind: str, plan: str) -> None:
        runner = _RUNNERS[kind]
        for sc in enabled_scenarios(load_plan(_ROOT / plan)):
            runner(self.controller, sc, self.bus)
Analogy The library is an interpreter at a meeting: the Robot file speaks "test language", the engine speaks "Python", and the interpreter passes messages faithfully between them.
Why HiltfLibrary.py with the .py? Robot resolves a bare name on the module path; giving the path (with extension) makes it load relative to the suite file, so the suites run from anywhere without extra setup.

The whole loop, one picture

Open Bench            -> load_config -> InstrumentController builds 4 sim drivers
Run All Cases         -> for each enabled Scenario: run_*_case(controller, sc, bus)
    keyword           ->   drive SignalGenerator, read Multimeter / Oscilloscope / DUT
    keyword           ->   publish("test.result", ...) to the EventBus
ReportRecorder        -> (subscribed) collects every result, grades each case
Write Report          -> render Markdown; All Cases Passed asserts no FAIL
Close Bench           -> disconnect all drivers

Run it three ways — all green:

pytest -v                                   # 21 unit + integration tests
robot --outputdir reports hiltf/layer1_suites   # 3 suites
python examples/run_all.py                   # end-to-end -> Overall: PASS

Capstone exercises

Capstone A — a new instrument. Add a SimPowerSupply driver (voltage in, current-limit out) that shares the bench, plus a PowerSupply protocol. Wire it into the controller. Prove Layer 2 didn't need to change to gain a new instrument.
Capstone B — a new test type. Add a run_ripple_case keyword and a ripple_plan.csv, reusing the event bus and recorder. Add a Robot suite for it. Notice you reused reporting for free.
Capstone C — a second report format. Add a JSON subscriber to the bus (Chapter 6) and emit reports/report.json alongside the Markdown, without editing a single keyword.
