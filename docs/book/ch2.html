Chapter 2

OOP building blocks

Before the layers, four object-oriented ideas the codebase leans on: classes, protocols (interfaces), context managers, and dataclasses. We meet each in a real file.

A class = data + the behaviour that goes with it

From hiltf/layer3_hal/base_driver.py — the parent every driver inherits:

class BaseDriver:
    def __init__(self, name: str) -> None:
        self.name = name
        self._connected = False

    def connect(self) -> None:
        self._connected = True

    def disconnect(self) -> None:
        self._connected = False

    def _require_connection(self) -> None:
        if not self._connected:
            raise RuntimeError(f"{self.name}: operation attempted before connect()")
Why self? A class is a template; an instance is one object made from it. self is "this particular object", so self._connected is the connection flag for this driver, separate from every other driver's flag.
Analogy The class is the blueprint for a walkie-talkie; each instance is a physical unit. They share the design (methods) but each has its own on/off switch (its own self state).
What breaks without _require_connection Call measure() before connect() on real hardware and you get a confusing socket error deep in a driver. This guard fails early with a clear message — a small habit that saves hours.

The context manager — guaranteed cleanup

Same file, the two "dunder" methods that make with work:

    def __enter__(self) -> BaseDriver:
        self.connect()
        return self

    def __exit__(self, *exc: object) -> None:
        self.disconnect()

Now anyone can write:

with controller as bench:      # __enter__ runs: everything connects
    run_the_test(bench)
# __exit__ runs automatically here: everything disconnects — even on error
Why bother? Instruments must be released whether the test passes, fails, or throws. __exit__ runs no matter what, so you can never "leak" a locked instrument session.

A Protocol — an interface without inheritance

From hiltf/layer3_hal/interfaces.py. A Protocol describes the shape an object must have, without forcing it to inherit from anything:

@runtime_checkable
class SignalGenerator(Instrument, Protocol):
    def configure_sine(self, channel: int, amplitude_vpp: float,
                       frequency_hz: float, offset_v: float = 0.0) -> None: ...
    def configure_dc(self, channel: int, level_v: float) -> None: ...
    def output_on(self, channel: int) -> None: ...
    def output_off(self, channel: int) -> None: ...
This is the hinge of the whole design. Layer 2 asks only for "something shaped like a SignalGenerator". A simulated generator and a real SCPI generator both have these methods, so both qualify — and Layer 2 can't tell them apart. That's how one test runs on simulation and hardware.
Analogy A power socket is a protocol. Any appliance with the right plug works; the wall doesn't care if it's a lamp or a laptop charger. The plug shape is the contract.

A dataclass — a labelled record, for free

From interfaces.py, the captured waveform:

@dataclass
class Waveform:
    dt_s: float
    samples: list[float] = field(default_factory=list)

    def times_s(self) -> list[float]:
        return [i * self.dt_s for i in range(len(self.samples))]
Why @dataclass? The decorator writes the boilerplate __init__ for you from the field list, so Waveform(dt_s=1e-6, samples=[...]) just works. default_factory=list gives each instance its own empty list — a classic Python trap avoided.

Key concepts introduced

class / instance / self__enter__ / __exit__Protocol (structural typing)@dataclass

Quiz 1 — Does a simulated driver have to inherit from SignalGenerator?

No. Because SignalGenerator is a Protocol, any object with the right methods satisfies it structurally — inheritance is optional.

Quiz 2 — When exactly does __exit__ run?

When the with block ends, for any reason — normal completion or an exception. That's what makes it safe for releasing hardware.

Quiz 3 — Why default_factory=list instead of = []?

A bare [] default would be shared across all instances (a mutable-default bug). The factory builds a fresh list per instance.

Exercise 2. In a Python shell, make a tiny class with __enter__/__exit__ that prints "open" and "close", and use it in a with block that raises an error in the middle. Confirm "close" still prints. You've just proven why the drivers are context managers.
