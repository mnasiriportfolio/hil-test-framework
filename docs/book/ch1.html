Chapter 1

The big picture

What are we building?

A Hardware-in-the-Loop (HIL) test framework: software that stimulates a piece of measurement hardware, watches how it responds, and decides pass or fail — automatically. In this project the hardware is simulated, so the whole thing runs on any laptop.

Analogy It's an automated exam for a device. We ask a question (drive a signal), watch the answer (read instruments), and grade it against an answer key (the spec in a plan file).

The three layers

The code is split into three layers, and the golden rule is that knowledge only flows downward — each layer knows less about the hardware than the one beneath it.

Layer 1  hiltf/layer1_suites/   Robot Framework specs — the test intent
              |  (calls keywords by name)
Layer 2  hiltf/layer2_engine/   the engine: plans, algorithms, event bus, reports
              |  (calls Protocol interfaces only)
Layer 3  hiltf/layer3_hal/      the Hardware Abstraction Layer + drivers
LayerKnows aboutNever knows about
1 · Suitestest intent, keyword namesPython, channels, addresses
2 · Enginethe HAL interfaces, spec mathwhich transport, IPs, SCPI strings
3 · HALthe real instrument / simulationwhich test is running
Why separate them at all? Because the reasons a test changes are different from the reasons the hardware changes. If test intent and wiring details live in the same file, every new bench is a rewrite. Separate them, and moving to a new bench touches one config file — nothing else.
What breaks if you ignore this Put an IP address in a Robot suite and you've welded that test to one bench. Read a raw voltage in the engine and Layer 2 suddenly "knows" about volts-to-amps calibration that belongs in Layer 3. The seams are the whole point.

A measurement's journey

Follow one overcurrent test from top to bottom and back:

  1. A .robot file (Layer 1) says Run All Cases overcurrent ...plan.csv.
  2. The engine (Layer 2) loads the plan, then for each scenario drives the signal generator and reads the oscilloscope — all through interfaces.
  3. The HAL (Layer 3) turns "drive a sine" into changes on the simulated bench, and "capture the relay" into a waveform.
  4. The engine finds the rising edge, compares timing to spec, and publishes a result to the event bus.
  5. The recorder, subscribed to the bus, collects results and renders a report.

Every chapter that follows zooms into one of these steps.

Quiz 1 — Which layer is allowed to contain an IP address or NI resource name?

Only Layer 3 (the HAL). It is the single place that knows how an instrument is actually reached. Layers 1 and 2 speak in abstractions.

Quiz 2 — Why can the same test run against a simulator and real hardware?

Because Layer 2 only ever calls interfaces, not concrete drivers. A simulated driver and a real driver both satisfy the interface, so they're interchangeable.
