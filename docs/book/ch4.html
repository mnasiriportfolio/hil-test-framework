Chapter 4

The simulated bench

This is what makes the whole project runnable with no hardware. One object, SimulatedBench, is the shared "reality": the drivers write to it and read from it. It is deterministic — same inputs, same outputs — so tests never flake.

The physics, in closed form

From simulation.py. A sine's RMS is its peak-to-peak divided by 2√2; the current channel's volts map to amps by a calibration constant:

def rms_v(self) -> float:
    if not self.enabled or self.waveform != "SIN":
        return 0.0
    fund = self.amplitude_vpp / (2.0 * math.sqrt(2.0))
    harm = math.sqrt(sum((vpp / (2.0 * math.sqrt(2.0))) ** 2
                         for vpp in self.harmonics.values()))
    return math.hypot(fund, harm)
Why closed-form instead of generating samples? We only need the answer (the RMS, the trip point), not a giant array. Closed-form maths is exact and instant — perfect for deterministic tests. The oscilloscope does build samples, but only because finding an edge needs a time axis.

The DUT's decision

def current_rms_a(self) -> float:
    ch = self.channels[self.cfg.current_channel]
    return ch.rms_v() * self.cfg.volts_to_amps

def overcurrent_tripped(self) -> bool:
    return self.current_rms_a() >= self.cfg.overcurrent_trigger_a
Analogy SimulatedBench is a flight simulator's physics engine. The yoke (signal generator) doesn't move a real plane; it updates shared state, and every instrument in the cockpit reads that same state consistently.

The oscilloscope builds a trace

From sim_drivers.py. Notice how little the driver does — it is a courier:

def capture_relay(self, relay: str, gate_ms: float) -> Waveform:
    self._require_connection()
    dt, samples = self.bench.relay_trace(relay, gate_ms, self.sample_rate_hz)
    return Waveform(dt_s=dt, samples=samples)

The samples themselves are rendered by the bench, in simulation.py. That matters: the networked emulators hold the same SimulatedBench object, so a trace fetched over a socket is sample-for-sample identical to this one.

dt = 1.0 / sample_rate_hz
n = max(1, int((gate_ms / 1000.0) / dt))
if not self.relay_states().get(relay, False):
    return dt, [0.0] * n
rise = int((self.detection_time_ms(relay) / 1000.0) / dt)
fall = rise + int(self.hold_time_s(relay) / dt)
high = self.cfg.relay_high_v
return dt, [high if rise <= i < fall else 0.0 for i in range(n)]
Why there is a falling edge. A relay doesn't latch forever — it holds, then releases. Rendering the release means one acquisition answers two questions: the rising edge gives the detection latency, and the width between the edges gives the hold duration. Asking the device how long it intends to hold would only read back its own opinion.
What breaks if the relay never trips The early return hands back a flat trace of 0.0. The keyword layer finds no level to threshold against, reports inf, and the timing check fails — exactly the right failure when a device doesn't respond. And note it is inf, not 0.0: inf fails a "<= limit" check, whereas 0.0 would sail through it.

Self-calibration lives here too

def analog_output_a(self, channel: int, requested_a: float) -> float:
    raw = requested_a * (1.0 + self.cfg.analog_output_gain_error)
    return raw * self.analog_correction

The DUT reproduces its input with a gain error. A test can later write analog_correction to cancel it — the mechanism behind Chapter 7's self-cal.

Quiz 1 — Why must the simulation be deterministic?

So tests and CI give the same result every run. Randomness would make a passing test occasionally fail for no real reason ("flaky" tests).

Quiz 2 — Where do real oscilloscope samples get created?

Only in capture_relay. Everything else is closed-form scalars.
